# 進化ダンジョン｜カードUI共通デザインルール

**状態：正式ルール（2026-10-13、ユーザー承認済み）。カード65種類すべてに共通枠を実装。実機の最終デザイン確認は未了。**

## 1. デザインの目的と正本

**「星の魔力を封じた、古代の魔導札」** をカード全体の共通コンセプトとする。

- イラストはゲームの主役であり、カード枠やテキストは鑑賞と判断を助ける。
- ハースストーンの立体的な存在感、Slay the Spireの即時可読性、遊戯王の情報階層を研究対象とし、枠や素材をそのまま複製しない。
- 表示の正本はユーザーが採用した防御V2（大きいカード）＋V3（戦闘中の手札）。[試作経緯](b1-defense-card-frame-prototype-20261013.md)。
- **このファイルは完成したデザイン上の正式ルール。カード57種類への実装は第1～3弾で段階的に行い、雷・結界8種類を第4弾で追加した。公開処理の成功と、PC・スマホ上での目視／ドラッグ動作確認は別の検証。**
- 画像生成・原画の制作ルールは `asset-factory/CARD_ART_RULES_DRAFT.md` が別正本。UIルールが画像そのものを作り直す許可にはならない。

## 2. カードの情報階層（全カード共通）

1. **原画**：カード上部を大きく占める。元画像を再利用し、剣・魔法・人物の主題が見切れない位置を選ぶ。
2. **魔力コスト**：左上に丸い青色の宝石。単なる数字ではなく魔力結晶として見せるが、数値の視認性を最優先する。
3. **種別紋章**：右上。防御はOS絵文字ではなくCSSの金色の盾形。攻撃・魔法・回復・状態異常・補助も一貫した小さな紋章で区別する。種類が違ってもコストの位置を動かさない。
4. **名前板**：イラストの下端に少し重ね、横長で細い金縁の深藍色プレートにカード名を置く。厚い浮いた装飾板には戻さない。
5. **効果欄**：名前板の下に深い藍色の領域。大きな文字、短い説明、装飾的な小さな星。**ベージュの広い空白・テキストと名前の重なり・カード内部のスクロールバーは禁止。**

## 3. 造形・色・文字

- カード本体は深藍～黒紺、外枠は細い古金、角の装飾は控えめ。防御V3を基準とし、厚すぎる四重枠を加えない。
- 役割別の色は**主に右上の種別紋章に限定**する。剣／物理は銅赤、魔法は藍・紫、回復は青緑、状態異常は紫、補助は金緑、防御は青銀・金盾。カード全体が別作品に見えるほど地色を変えない。
- 魔力宝石は原則青色。強化済みカードの専用演出やレア演出と混同しない。
- カード名は短く強く、明るい象牙色。効果は「防御5」「5ダメージ」のように、ゲームの日本語表記を改変せず明示する。
- 効果・コストは必ず `getB1Card(id)` の現在の値を使う。見た目のために効果数値を描き直したり変更したりしない。

## 4. 大きさと操作による表示の違い

| 表示面 | デザインルール |
|---|---|
| **戦闘中の手札** | イラスト約64％（低い横画面61％、極端に低い画面58％を目安）。名前板をイラストと効果の境目に10～12pxだけ重ねる。名前・効果は**絶対位置ではなくカードの実際の高さに従う**。1～2行を優先し、長文は持ち上げた拡大表示とアクセシビリティ説明で補う。 |
| カード拡大 | イラストを大きく見せつつ、効果は切らずに全文表示する。手札に比べて余白・文字を大きくする。 |
| 勝利報酬 | 3択の大型カードで原画を主役にする。必要なら報酬の外側全体をスクロールし、カード内部にはスクロールを置かない。 |
| 図鑑 | 同じカード構造を縮小表示。カードの種類・魔力・効果を読めること。長文の全文確認は拡大または別のテキスト表示を使う。 |
| 商店・カード削除 | 同じ顔のカードを使い、価格・削除などの独自UIは別途明示。対象の選択範囲やカード操作は変えない。 |
| **休憩所の進化選択** | 既存の専用金色カードが優先。強化前と強化後の実効果・コストを並べ、通常カード枠で上書きしない。 |

### 実機フィードバックに基づく拡大・進化画面の制約（2026-10-13）

- 戦闘中にカードへマウスを重ねたときの拡大表示は、**戦闘画面を覆うような巨大カードにしない**。上限は280 CSS px、画面高さの58％以内で、小さな手札よりひと回り大きく表示する。カード選択・ターゲット指定・ドラッグの操作は変えない。
- **進化カード選択では見出し・説明・「戻る」を固定し、中央の候補カード一覧だけを縦スクロール**する。全画面ウィンドウと一覧を二重にスクロールしない。候補一覧は `flex:1 1 0`、`height:auto`、`min-height:0` を使用し、長いデッキの末尾まで到達できるようにする。
- ブラウザの表示倍率を上げてもカードの過剰拡大や上下のスクロール競合を起こさない。CSSの色・レイアウト変更と実機の操作確認は別の作業として検証する。

## 5. 機能とアクセシビリティを守る

- UI調整で、カード画像・元の戦闘効果・ターゲット選択・カード枚数・報酬抽選・セーブ・旧本編を変更しない。
- 手札のタップ・ドラッグ・持ち上げ・左右スクロール・キーボード操作を維持する。`touch-action`・`pointer-events`・`transform`・手札の当たり判定は既存システムが正本。装飾疑似要素はクリックを奪わない。
- 数値・効果は装飾色だけに依存させない。ボタンの `aria-label` には名前、魔力、実効果を含める。アクセシビリティと色のコントラストを担保する。
- 長い説明でカード下部が溢れる場合は短い手札表示に限り行数を制限し、拡大画面では全文を示す。長文を無理に1行へ圧縮しない。
- 動きを減らすOS設定を尊重する。既存のドラッグ・フォーカス演出を装飾CSSから壊さない。
- PCとスマホ縦・横、低い横長画面で、コスト・名前・効果欄の重なりを確認する。

## 6. 実装の構成と段階

- 共通の生成箇所は `v4-1/underground-b1-playtest.html` の `cardButton(id)`。
- 承認済みV3を一般化した共通CSSは、現段階では既存の `v4-1/underground-b1-defense-prototype.css` を再利用する。適用クラスは `.b1-arcane-card`、役割クラスは `.b1-frame-guard` / `.b1-frame-physical` / `.b1-frame-spell` / `.b1-frame-heal` / `.b1-frame-debuff` / `.b1-frame-skill`。
- **第1弾：15種類適用（防御1＋新規14）**。対象は `basicAttack`, `basicDefense`, `guard`, `bolt`, `lightning`, `frost`, `scatter`, `chain`, `heal`, `drain`, `poison`, `fragile`, `strength`, `spark`, `break`。魔法原画のある基本カードと、回復・状態異常・補助の代表例。
- **第2弾：追加22種類、合計37種類適用。** 炎属性（火弾・灼流・獄炎砲・火の雨・炎の波・業火の嵐）、雷（雷針・双雷槍・天雷・双雷）、氷（氷の結界・霜砕き・返響の盾・氷槍）、魔力（術式循環・魔力点火・魔導の研究・魔力槍）、毒炎・余毒の頁・闇弾・奈落弾。CSSの共通イラスト領域は元の炎の画像スプライトにも対応し、画像原本には触れない。
- **第3弾：最後の20種類を追加。合計57種類すべて適用。** 精神崩壊・呪い・死の歌声・幻覚・影の反響・吹雪・雷の奔流・導魔突き・魔装斬、物理系（殴打・連続殴打・強打・急襲・鉄槌・ドーピング・逆境・逆鱗）、竜の卵・竜の餌・竜息が対象。
- **第4弾：雷連鎖・結界カード8種類を追加、全65種類に適用済み。** 背景スプライトは元の画像を優先し、枠CSSの背景色で炎・竜の原画が消えないようにする。長文カードは手札で最大2行に収め、拡大すると全効果が読める。ゲームの効果・デッキ・保存・報酬・旧版は不変。
- 既存の進化比較画面では `.b1-arcane-card` を外して専用金色UIを優先する。
- 変更のたびに `tests/astral-underground-b1-unified-card-frame.test.mjs` などで対象枚数、CSS/JS、操作回帰と元のカード数値を検証し、GitHub Pages公開と実機確認を区別する。

## 7. 合格基準と戻し方

合格基準：①防御を基準としてカードの見た目が揃う、②どのサイズでも「コスト→絵→名前→効果」を読める、③手札のタップ・ドラッグで元どおり使用できる、④実ゲームの効果・抽選・保存が変化しない。

**戻し方：** 第3弾のPRをrevertすると37種類、第2弾をrevertすると15種類へ戻る。最初の第1弾も個別にrevert可能。前回の防御V3や原画は履歴に残っている。原画の差し替えやゲームシステムの巻き戻しは不要。

## 8. 残すべき判断

- このデザインは**ユーザー承認済み**。大幅な方向転換や全カードへの一括破壊的置換は行わない。
- 画像を一枚の静止画として貼るのではなく、ゲーム内のボタンと効果・ドラッグの上にデザインを載せる。
- 新規カードの作成とカードデザイン統一は別タスク。**カード総数は第4弾で65種類**。

## 2026-10-14追補：スマホの報酬と手札（ユーザーの実機フィードバック）
- 横向きスマホでは、勝利報酬は3枚を**横並びで同時に表示**し、基本的に下スクロールを必要としない。PC版は大型3枚、縦向きスマホは縦一覧を維持。スマホ横向きでは原画を35％（低い画面27％）とし、名前とカード効果全文が重ならないことを優先する。

- 変更確認を容易にするためスマホの⋯設定に表示中の版番号と更新ボタンを設ける。プレイ中の更新は進行を失う可能性を警告する。詳しくは[判断記録](b1-mobile-reward-three-update-20261014.md)。
