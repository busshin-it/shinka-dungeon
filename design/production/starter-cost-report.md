## 目的と範囲

ユーザーの「最初のカードがすべて0コストで、全部使うのが正解になっている。コストを持たせる」という指摘への小さな改訂。
新しい旅だけ「小さな魔弾」「薄い守り」を各1コストにする。攻撃/防御は3、進化後5のまま。
初期魔力2、2ターン目以降の自然回復を3、上限5、余剰の持越し。星渡りの回廊の第4〜6戦の開始3は維持する。

1枚使うごとに攻撃・守り・次の札に残す魔力を選ぶ。回復1のまま有料化すると行動数を極端に絞るため、回復3を同時に試す。
ただし難易度・回復量・楽しさは仮値であり、適正を断定しない。無料の報酬札は従来のまま残る。

- 新カード、新しい敵、画像、ルート、クラス、レイアウト、依存追加、Asset Factory設定変更は含まない。
- PR #14〜17の設計提案は別件。この公開に取り込まない。
- 図鑑は基本2＋報酬50の52種。基本札は報酬候補にしない。
- 原仕様の開始2/回復1という思想の改稿ではなく、6戦の成長試遊に限定した経済ルールの比較。

## 保存・表示の境界

- 新しい旅：保存version5、`ruleset: growth-v2`。既存のgrowthフィールドを使い、追加の状態フィールドは作らない。
- 以前のgrowth-v1/version4：基本札0コスト・自然回復1のまま再開・再保存。途中の保存を新ルールへ変換しない。
- classic/version3、v1/v2移行、24枚版は従来どおり。カード、敵、報酬候補、RNG、開いていた選択肢を保持する。
- `card(id)`と`CARDS`は旧定義のまま。`card(id,state)`と`game.card(id)`がプレイ中のルールに応じたコストを返す。
- 手札、選択パネル、図鑑、デッキ、進化カードは同じrun内の解決を使う。魔力欄と遊び方も再開した保存に応じた回復量を示す。
- versionとrulesetが食い違う保存は拒否する。拒否時に現在の状態/RNGを変更しない。
- 「最初から」「新しい旅」は新ルール。旧保存を続けたい場合は「続きから」。更新のために保存を消す必要はない。

## 同じ条件で測った結果

24seed×3護符×2ルール、beam6。全72組が各戦へ到達し、操作上限/未処理による停止は0。支度は各護符8seedで、各ルールの同じ保存から休息・基本魔弾進化・基本守り進化・基本魔弾除去・基本守り除去を比較した。自然HPと合成HP20/60を分離する。実行時間195.416秒。保存/次操作/RNGの比較36,831回。

| 指標（1ラン平均） | 公開4.15のgrowth-v1 | 4.16のgrowth-v2 |
|---|---:|---:|
| 最初の報酬までのターン | 2.000 | 3.083 |
| 最初の戦闘のカード使用 | 7.000 | 6.333 |
| 最初の戦闘の操作（カード＋ターン終了） | 8.000 | 8.458 |
| 全体ターン | 31.375 | 35.514 |
| 全体カード使用 | 112.986 | 80.014 |
| 全体戦闘操作 | 139.403 | 110.167 |
| メニュー込みの操作 | 161.028 | 131.806 |
| 全6戦完走 | 45/72 | 46/72 |

カード使用は約29.2%、戦闘操作は約21.0%減った。一方、ターンは約13.2%増え、初報酬も遅くなった。**入力が減るという結果であり、ゲームが一律に速くなるとは言えない。** 初手の基本札は5枚のうち2枚までになるため、全部使うだけでは進まなくなる。

両方で完走した27組に限っても、新候補は平均ターン+3.815、カード使用−38.593。途中敗北による打ち切りだけで操作数が減ったわけではない。ただし同じseedでも選んだ操作やシャッフル時機が変わるので、以降の報酬/山札が常に同じになる比較ではない。

護符別完走は氷晶15→13、雷鳴14→19、月鏡16→14（各24）。合計1件増から全護符の改善や勝率の上昇を主張しない。

自然HPの支度24件では、新候補の次戦終了時の勝敗/HP/ターン順で休息が単独最良11、魔弾進化2、守り進化4、同率7。旧版は魔弾進化3、魔弾除去12、守り進化1、同率8。今回は新候補の自然データにも休息が効く場面がある。HP20に変更した合成データは両ルールで休息24/24が最良で、自然データと混ぜない。除去の長期価値や最適方策はこの次戦だけの比較では判断しない。

基準と現行の旧growth-v1を9ランで別に照合し、測定行と支度保存が一致。独立した固定データでも旧growth54経路・24自然ラン、78件のv1〜v4保存・次操作が一致する。旧52カード定義も不変。

## 表示確認の限界

独立コードレビューでは、新旧の手札・選択・図鑑・デッキ・進化が同じactive-runカード定義を参照していることを確認した。依存を追加しないDOMスタブで表示文字列と操作経路を検証したが、これはブラウザの実描画の合格ではない。

headless Chromiumは実行環境のsocket制約で起動できず、クラウドブラウザもローカル検証URLを`ERR_BLOCKED_BY_CLIENT`で拒否した。その経路を停止し、回避していない。実ブラウザやスクリーンショットのQA合格は記録しない。
